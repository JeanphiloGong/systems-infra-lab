# 在 main 上从零学习

`main` 是你的练习工作区。安装依赖和启动数据库不会生成实验实现；只有按教程创建文件后，相应程序才可运行。教程里的 `labs/...` 是目标路径，`tests/...` 只有在教程明确给出创建步骤后才会存在。

第一次从 [T01 v0](../tutorials/02-transactions-isolation/01-isolation/v0/tutorial.md) 开始。每版按“创建或修改文件 → 执行本步命令 → 对照输出或断言 → 进入下一步”的顺序完成。v0 是本专题的起点；v1 及以后依赖前版已创建的文件，不能直接跳到最后一版运行。

## 文件如何保存

正文写“新建”时，先创建父目录，再保存完整代码。例如：

```bash
mkdir -p labs/transactions/isolation
```

正文写“替换整个文件”时，只替换指定文件；写“在某函数后追加”时，保留其他代码。同页给出多个文件时，先保存所有依赖，再执行依赖它们的命令；不要在缺少后文文件时提前运行。独立演示片段只用于理解，不自动成为最终文件的一部分。不要把 SQL、shell 和 Python 代码混存到同一个文件。

有些实验的完整文件标为 `checkpoint.py`、`model.py` 或 `postgres.py`，且没有目录。这表示仓库根目录的临时实验文件，按该页名字保存；后续替换前先保存自己的进度。带完整 `labs/...` 路径的代码则保存到对应目录。`<!-- checkpoint: ... -->` 是作者用于提取代码的标记；可见的正文或文件名才是操作说明。

`uv run python -m labs....` 从仓库根目录运行。当前采用 Python 的命名空间包机制，纯 Python 实验无需为了导入而复制空的 `__init__.py`。某些版本提供两个相互导入的文件，应先保存两份再运行。

## 如何验证自己的实现

优先执行当前页给出的直接运行命令、断言或手工故障实验。预期抛异常的命令应单独运行；非零退出码可能正是该步希望观察的结果。不要把所有命令串成一个必须全成功的 shell 脚本。

T01 从 v0 开始提供完整测试文件，并在后续版本追加用例。其他专题若只有测试场景说明，先完成当前页的直接实验；不要创建空测试文件来让 pytest 通过，也不要把“没有测试被收集”当作验证成功。

旧的 replay/pytest 命令集中在各页的“可选：参考分支验证”折叠区。它们只用于 [参考答案检查](reference-checks.md)，不会验证你尚未写出的实现，也不应成为进入下一步的条件。

## 参考答案与历史证据

本地 `reference` 分支保存此前完整答案，默认不把它合并回练习分支。需要对照一份文件时，先查看：

```bash
git show reference:labs/transactions/isolation/transfer.py
```

参考分支保存的是当时的最终代码；旧 v0、v1 应以对应教程的完整代码和前置文件为准。`docs/progress.md` 与 `.agent-runs/` 保存历史作者审核，不能替代对你当前代码的检查，也不等于你已经学完。

一个版本完成后，再按需要保存自己的 Git 检查点。教程文件已经在仓库中，不意味着实验文件也应该提前存在。
