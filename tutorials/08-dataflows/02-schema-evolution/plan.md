# E02：Schema Evolution 模块计划

状态：依据当前实验补齐模块计划，待独立审核。本文不改变历史测试结果，也不把
尚未执行的验收写成成功。前置为 E01 的生产者/消费者切点和 Q01 的表约束。

## 场景与契约

旧客户端只认识 `name`，新客户端希望读取必填 `full_name`。发布不能同时更新
所有客户端，因此数据库、写入方和读取方会经历不同版本组合。沿用现有 `profiles`
表压缩这个问题：五条记录、两个字段、一个持久回填游标，不实现部署平台。

调用者应能在兼容阶段继续使用旧协议；最终清理后旧协议明确失败。迁移过程必须
区分读取兼容、写入兼容和事件载荷兼容，不能用一次成功 SELECT 证明全部成立。
不变量是：每阶段声明的客户端组合确实可用；回填数据与游标同事务提交；新客户端
已经写入的值不被回填覆盖；最终约束与过渡字段清理可从数据库查询和失败写入验证。

## 依赖与编写任务

1. **v0：暴露破坏性发布。** 从旧客户端成功写入/读取开始，先演示现有直接改名的
   `UndefinedColumn`，再补路线图要求的必填字段反例：空表增加无默认值的 NOT NULL
   字段后，旧 INSERT 因缺字段失败；已有行时直接增加该字段也可能在 DDL 阶段失败。
   两种失败不能混为一谈。目标为 `v0/tutorial.md`、`labs/dataflows/schema_evolution/v0.py`
   及提取重放测试。冻结完整失败基线，下一步只增加兼容字段。
2. **v1：扩展 schema。** 增加可空字段，以 `COALESCE(full_name,name)` 读取旧行，
   新客户端在过渡阶段双写。逐项检查旧写后新读、新写后旧读和历史行读取，而不仅
   观察加列成功。旧写仍可能留下 NULL，作为 v2 的输入；不能声称已经满足最终必填约束。
   必须对同一行执行新客户端双写、新客户端读取、旧客户端仅更新 `name`、新客户端
   再读的完整轨迹。例如先写 Ada Lovelace，再由旧端更新为 Ada Byron，新端必须得到
   Ada Byron，不能因 `COALESCE` 优先选择非空旧 `full_name` 而返回 Ada Lovelace。
   迁移窗口明确以 `name` 为唯一权威写入字段：新端双写但读 `name`；停止旧写、按
   当前 `name` 做最终同步后才切换至 `full_name`。最终版本移除该过渡读写协议。
3. **v2：可恢复回填。** 从缺失 `full_name` 的行开始，以主键顺序每批两行更新。
   数据更新与 `schema_backfill_checkpoint.last_id` 同事务提交，在提交前后分别让
   worker 退出。现有实验期望游标为 2、剩余待回填的 3/4 行不被未提交事务改变、
   恢复后无 NULL，ID 5 保留 `Protected by new client`。审核时核对这些值来自真实查询，
   重复 worker 返回零工作量，且不能用预填常量代替子进程返回证据。
   游标经过的行不能再被旧写入重新置空；停止旧写入或另外扫描落后数据的前提必须写明。
   实验初始化需要同时清理 `profiles` 与 `schema_backfill_checkpoint`，只在初始化
   时清理，worker 重启必须保留进度。对同一专用数据库连续运行两次完整 v2 实验，
   两次都应成功且观测相同，不能因残留 checkpoint 表触发 `DuplicateTable`。
4. **v3：收紧并清理。** 在明确旧客户端退出且无 NULL 后设置 NOT NULL，删除 `name`
   和回填临时状态，保留纯新协议。查询系统目录确认列/约束，尝试 NULL 写入并断言
   `NotNullViolation`，新协议读写成功、旧协议明确拒绝。仅返回 `not_null=True`
   不足以验收。最后提供完整当前代码并重放。

每版对应的 `vN/plan.md` 进一步拆分写作任务；代码检查点使用现有 `common.py`
和 `vN.py`，正文必须列全依赖。所有教程需要说明为什么前一版不足，以及本版
引入机制后的剩余限制，而非只给最终程序。

## 事件 schema 的独立验收

路线图还要求区分事件 schema。需要在本模块增加小型生产者/消费者兼容矩阵：
旧消息仅含 `name`、过渡消息同时包含两字段、新消息只含 `full_name`；分别验证
旧消费者、新消费者对三种消息的行为和明确拒绝路径。过渡期新消费者读取旧字段
只属于本实验迁移步骤，最终检查点删除过渡读取逻辑。该实验尚未由现有表迁移测试证明；
不能引用 PostgreSQL 回填通过作为其验收证据，也不能把它静默移出 E02 的范围。

## 重放与交付

从仓库根目录运行专用服务，避免接触其他数据库：

```bash
docker compose -f infra/e02.compose.yaml up -d --wait
E02_DATABASE_URL='postgresql://e02:e02_local_only@127.0.0.1:55451/e02' uv run pytest tests/dataflows/schema_evolution -q
docker compose -f infra/e02.compose.yaml down -v
```

`tests/dataflows/schema_evolution/test_e02_replay.py` 将各版完整围栏提取到临时目录，
核对源码一致并执行。新增反例、兼容矩阵及失败写入必须加入该验收路径后，才可
关闭范围缺口。当前历史测试只覆盖改名、可空扩展、回填和删列的部分观察。

交付顺序：计划审核、逐版修订、作者运行、独立提取重放、复审关闭；不自动提交 Git。
边界为固定 PostgreSQL 版本和受控调度，不声称无锁在线 DDL 或任意客户端滚动升级安全。
