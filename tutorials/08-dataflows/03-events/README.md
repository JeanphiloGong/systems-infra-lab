# E03：事件溯源与反规范化读模型

订单当前状态只能回答“现在是什么”，事件流还要回答“怎样变成现在”。本专题使用 SQLite 事件日志和投影表压缩这个问题：事件是事实来源，版本是并发边界，投影是可丢弃的读优化。

- v0：当前状态表无法解释历史。
- v1：追加事件并按顺序重放，拒绝非法状态转换。
- v2：expected version 让并发追加显式冲突。
- v3：带消费位置的反规范化投影可重复消费并从头重建。
- v4：upcaster 兼容旧事件；重建只改变状态，不发送外部副作用。

这些是本地 SQLite 教学模型，不是 CDC；事件由领域写入，事实来源与已有存储的变更捕获不同。每版源码都由测试提取到空目录并独立运行。
