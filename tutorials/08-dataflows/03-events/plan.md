# E03 总计划

目标：追溯订单状态变化并重建读模型。事实是有序 `(stream, version, kind, payload)` 事件；派生表可以删除重建；外部发送只发生在新事件命令路径。

1. v0 以当前状态行展示历史缺失。
2. v1 用 SQLite 持久事件和有限状态转换重放。
3. v2 在同一流上以 expected version 原子追加，旧读者得到冲突。
4. v3 记录 `(stream, version)` 消费位置，重复消息不重复投影，滞后投影可从头重建。
5. v4 upcast 旧 payload，重建与副作用 dispatch 分离。

验证：每版完整 fence、临时目录独立解释器、状态/冲突/去重/副作用断言。边界：单 SQLite 进程、无跨服务事务、无 CDC 全局顺序、无分布式投影协调。
