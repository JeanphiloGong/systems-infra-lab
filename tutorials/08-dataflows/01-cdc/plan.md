# E01：CDC 与投影同步的模块计划

订单源库已提交并不表示读模型已更新。本模块从应用双写中断开始，用专用
PostgreSQL 16 的 logical slot 捕获提交后的变更，再把它们应用到独立投影。
前置为 R04 的逻辑复制边界；服务、端口和清理命令见本目录 README。

模型包含源表、slot、带 LSN 的事件、投影和消费 checkpoint。不变量是：源确认
不得先于目标提交；同一批重放不得使投影偏离源状态；DELETE 必须删除旧行，随后
同 ID 的 INSERT 必须产生新实例。测试使用固定表与单消费者，不宣称通用 CDC 引擎。

## 版本任务

1. **v0：让双写失败可见。** 源库写入成功后中断投影写入，比较两边状态。
   冻结不一致的反例，说明仅在应用代码里顺序调用两个写入不能提供跨库原子性。
2. **v1：读取已提交的逻辑事件。** 创建 test_decoding slot，保留源 LSN、事件身份
   和操作类型；从实际解码结果检查提交顺序。此版有增量流，但新消费者还没有历史数据。
3. **v2：在有写入阻塞的切点衔接快照。** 先建 slot，再在事务内取得 orders 的
   SHARE 锁、读取快照、消费快照覆盖的事件并记录 confirmed_flush_lsn，然后释放锁。
   解释写入会短暂阻塞，不能把该协议描述为不停写快照。切点后执行 UPDATE、DELETE
   和同 ID 重建，应用增量后核对完整投影等于源表，且 cursor 早于最后事件位置。
   此版仍未证明快照初始化过程的崩溃恢复。
4. **v3：原子提交增量批次。** 把投影变更和 checkpoint 放在同一 SQLite 事务中，
   目标提交后才确认源 slot。用独立 worker 在提交前后退出，再由新进程重放。
   检查提交前两者回滚、提交后可重复应用、确认位置仅在恢复完成后前进。
   该证明以已初始化的快照为起点，不涵盖首次快照与 cursor 的原子发布，也不提供
   对任意外部副作用的 exactly-once 保证。
5. **v4：观察暂停消费的代价。** 暂停 slot 消费后产生写入，测量 WAL 保留位置差；
   恢复消费后检查 confirmed_flush_lsn 前进。位置差是实验观测，不等于整个数据库
   的磁盘占用；跨节点顺序、slot 丢失和生产容量规划仍超出本模块。

每版的输入、断言、完整代码与命令由对应 `vN/plan.md` 和 `vN/tutorial.md` 给出。
作者先执行当前版本检查，再交独立审核者从围栏提取到临时目录重放。

## 验收与交接

启动 README 指定的专用服务并设置 `E01_DATABASE_URL` 后运行：

```bash
uv run pytest tests/dataflows/cdc/test_e01_replay.py -q
```

验收检查包括 v0 的不一致、v1 的源事件身份、v2 的混合操作衔接、v3 的三个 worker
退出边界和 v4 的保留/确认位置。围栏与对应源文件须一致；缺少服务导致的失败不得
记为通过。使用同一 compose 文件清理本模块服务，保留实际审核证据；不自动提交 Git。
