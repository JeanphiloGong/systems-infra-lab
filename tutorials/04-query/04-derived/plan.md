# Q04 实现计划

场景是每日销售仪表盘。核心数据为销售明细、日汇总、缓存值和新鲜度边界；不变量是派生数据的旧读必须明确可见，不能冒充实时数据。沿用路线规定的 `labs/query/derived`，教程为 `04-derived`。

1. v0：真实 GROUP BY 建立每日 10,000 的正确性基准，记录两次 EXPLAIN ANALYZE BUFFERS。
2. v1：创建物化视图，源数据写入后观察旧总额；显式刷新后恢复一致，对比数据库实际读取成本。
3. v2：两个连接验证普通刷新/读者互相阻塞，并发刷新与普通读取兼容；验证唯一索引和已填充视图前提。
4. v3：回源真实 PostgreSQL 的 cache-aside，注入时钟验证未命中、命中、到期点和源异常不缓存。
5. v4：Event 协调真实数据库读写竞态；失效之后的旧填充被 epoch 拒绝并重试；报告受控调度中的旧读窗口及提交到失效之间的残余窗口。

每版完整代码围栏只包含公共数据库准备、该版使用的缓存实现以及本版实验入口。严格 replay 从正文提取，临时目录中新进程执行，缺少数据库环境时失败。每次实验随机 schema，finally 清理；不提交 Git、不改其他模块。缓存是单进程单键教学实现，逻辑时钟的窗口不是生产 SLA，数据库锁等待另用墙钟测量。
