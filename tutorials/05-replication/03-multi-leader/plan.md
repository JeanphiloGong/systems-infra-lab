# R03 教程实施计划

读者已完成 R01 复制进度、R02 读取契约和 C01 分区实验。场景是两个地区的用户修改同一个展示名称，随后把业务换成可累加访问量。路线保持 roadmap 的 v0-v4 范围；不实现生产跨地区数据库。

压缩模型包含 A/B 两地区、离散事件网络、地区本地处理延迟、分区、版本和确定性合并。时间单位是模拟毫秒，数据只在内存中。每条成功写入的延迟必须来自调用开始与确认事件的时间差；收敛不等于业务更新全部保留。停止写入且最终交付当前状态是本实验收敛的前提。

1. v0（M）：用户在 B 写入 A 主节点，需要完整跨区往返。先实现可追溯的事件调度，再测 A/B 写入开始和确认的差值。目标 v0/tutorial.md、v0.py；验收 local=2ms、remote=82ms，并改变单程延迟验证差值不是常量。产出完整 checkpoint；前置 R01/R02/C01；下一缺口是分区时 B 无法写入。
2. v1（M）：从 v0 的统一写入口改为两地区本地确认。对同键并发写保留向量版本及冲突值，分区修复后交换状态仍必须呈现两个候选。目标 v1/tutorial.md、v1.py（完整引用 v0.py）；测试本地确认、因果覆盖与并发冲突。前置 v0；下一缺口是如何选择一个可展示值。
3. v2（M）：仅为标量寄存器选择确定性的时间戳/地区/序号全序；保持事件网络与本地确认契约。目标 v2/tutorial.md、v2.py（完整引用 v0.py）；测试交换顺序、重复、时间戳相等，以及偏快的早写覆盖真实较晚写。必须说明丢失的成功更新。前置 v1；下一缺口是计数相加不能使用标量赢家。
4. v3（M）：只对递增计数设计按作者分量取 max、最终求和的 G-Counter。目标 v3/tutorial.md、v3.py；对快照的所有排列和重复传输验证无重复累加、旧快照不回退、最终等于两作者增量和。前置 v2；说明身份唯一/状态不能重置等边界。
5. v4（M）：用 v0 单主与 v2 多主跑同一 A/B 工作负载，分别连接、分区、修复。目标 v4/tutorial.md、v4.py（打印所有依赖）；从请求记录计算成功数、确认延迟、超时延迟及同键冲突损失；单主也有跨地区副本。前置 v0-v3；说明单键示例、无负载队列、无磁盘、无吞吐测量。

所有版本均需中文解释、完整源码围栏、公开可执行检查围栏、版本特定预期结果。测试只提取正文文件到空目录，在独立进程执行正文检查，不从仓库补依赖；再核对源码与正文一致。最终变更只涉及 R03 路径；不提交 Git、不改共享进度。审核重点：隐藏未来代码、LWW 时钟偏移反例真实性、计数器幂等合并、测量口径和模拟/生产边界。
