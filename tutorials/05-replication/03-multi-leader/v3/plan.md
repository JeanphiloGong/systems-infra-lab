## 场景与契约

两地区分别累计访问量，需要保留双方所有增量。 读者需掌握 Python 与 R01/R02/C01 的复制、读取契约与分区。先重放 [v2](../v2/tutorial.md)，再扩展本篇行为。 模型只保留A/B 两地区、逻辑事件、版本元数据和确认轨迹；不变量是确认、冲突和收敛各自可追溯，合并丢失不得称为无损同步。

## 有序写作任务

1. **Pressure:** 两地区分别累计访问量，需要保留双方所有增量。
   **Naive:** LWW 覆盖计数会丢一次加一；重复投递加一消息又会多计。
   **Break:** A 旧快照分量为 2、新快照为 3，B 为 4，传输顺序与次数不应改变总和。
   先在正文给出该调用轨迹，标明观测时刻及已发生的状态变化，作为后续修改的比较基线。

2. **Change:** Counter 只增加本作者分量；snapshot 返回独立副本；merge 逐分量 max，value 求和。
   依赖任务 1；目标为 `labs/replication/multi_leader/v3.py` 的相关方法及 [本版正文](tutorial.md) 的调用说明。解释谁修改状态、读者从何处取得输出。
   **Check:** check_v3 遍历快照排列及重复传输，分量恒为 A=3/B=4，总数 7；缺 B 时只有 3，补 B 才为 7；非法输入不改状态。
   验收不能只检查“运行成功”，要逐项核对结果、错误或进度。

3. **Freeze:** 依赖任务 2；正文必须保留 v3.py 的完整 checkpoint 围栏及 check_v3.py 检查围栏。从正文提取所有文件后重放，不借用更新后的仓库模块。
   **Still-lacks:** 依赖唯一且持久的作者身份与不回退分量；不支持删除/递减或任意业务字段。
   **Next:** v4 回到展示名称，用同一负载比较单主与多主的代价。
