# S01 写作计划

读者：能编写 Python 文件读写程序，尚未实现页式读取。目标：保持查询结果不变，解释扫描、直接定位、页放大和缓存命中分别改变了什么。

真实场景是百万订单点查询，压缩为按编号排列的固定 8 字节记录 `(uint32 key, uint32 value)`。这是教学假设：编号恰好等于槽位，值为编号乘十；不支持变长记录、删除洞或并发写入。核心模型是记录、字节偏移、页和访问序列。不变量是各路径返回相同值、截断记录不静默接受、缓存不超过容量、所有测量明确数据规模与缓存层次。

依赖图：生成文件 → 扫描并数实际返回字节 → 按槽位定位 → 组装跨页记录 → 相同集合的两种访问顺序 → 有界应用缓存。

1. v0 从读取第 0 与最后一条订单的差异引出字节计数。验收首尾缺失、空文件与截断；完整目标 `records.py`。规模 S，无前置模块。
2. v1 查询末尾仍扫描全文件，引出 `key * RECORD.size`。验收所有槽位、负数、越界、损坏槽位；完整目标仍为 `records.py`。规模 S，依赖 v0。
3. v2 记录 1 的区间 `[8,16)` 在 10 字节页中跨界，引出循环拼接页。验收页内、跨页、尾页、非法页长；新增 `paged.py`。规模 M，依赖 v1。
4. v3 同一批记录的连续与乱序读取，引出固定种子的工作负载和逐请求计时。验收集合相同、结果相同、页请求和不同页数可解释；新增 `workload.py`。规模 M，依赖 v2。
5. v4 重读同页仍读取文件，引出有界 LRU。验收冷热、淘汰再读正确、跨页容量为一、不超容量；修改 `paged.py` 并更新测量调用。规模 M，依赖 v3。

各版本 plan.md 细化写作任务与检查；正文以故障或可见成本开头，最后一步提供完整当前文件，不引入隐藏代码。每篇完成后先重放，再独立审核，再修改并重放。当前不提交 Git；审核通过后可由用户决定保存检查点。

辅助函数仅在调用者需要时出现：`write_records` 准备唯一数据格式；`scan/direct` 返回值与读取量；页读取对象承载累计读取统计；工作负载生成器保证公平比较。审核重点是页边界、Python 缓冲与 OS 缓存解释、计时不能作硬件结论、旧版本是否独立可运行。
