# P01：订单应该写到哪个分片

目标：调用者输入订单 ID，路由到一个分片；在同一配置下写入与读取位置一致。
读者会 Python 字典、排序和哈希基础。场景是订单数量超过单节点的容量，
压缩为内存中的节点名和整数订单 ID，不引入网络或数据库驱动。

不变量：路由确定；一个键只有一个主要归属；比较扩容时使用相同键集合与稳定哈希。
范围分区约定左闭右开，一致性哈希环规定顺时针查找和尾部回绕。
计数键归属不等于测量请求负载，路由变化不等于数据迁移。

## 有序写作任务

1. v0 从 `put/get` 的外部行为建立一个单分片订单字典，缺失键返回 None。
   验收：覆盖写入、缺失读取及范围扫描顺序；目标 `v0/tutorial.md`、`labs/partitioning/routing/single.py`。
   规模 S，checkpoint，前置无。完整代码加内联断言可独立执行。
2. v1 面对多个节点，添加稳定哈希取模路由；先演示 N 改变如何令旧键搬家。
   验收：同键确定性、所有结果属于节点集合、N=3→4 移动比例可复现。
   目标 `v1/tutorial.md`、`hashing.py`，规模 M，checkpoint，前置 v0。
3. v2 面对范围查询需访问所有哈希分片的代价，替换为明确分界的范围路由。
   验收：边界键、空范围、跨分片范围与递增键热点；目标 `v2/tutorial.md`、`ranges.py`。
   规模 M，checkpoint，前置 v1。替换实验策略而非通用路由接口。
4. v3 回到节点增减引起大规模迁移的问题，引入哈希环与虚拟节点。
   验收：环回绕、同集合配置确定性、新节点只接收原有节点移出的键、与取模迁移比例对照。
   目标 `v3/tutorial.md`、`ring.py`，规模 M，checkpoint，前置 v1、v2。

每个版本使用 `tests/partitioning/routing/` 对应检查，同时从正文重放完整代码。
测试数字只解释该键集和哈希算法，不给出普遍均衡保证。最后一版对比四种模式的读取代价和迁移边界。
