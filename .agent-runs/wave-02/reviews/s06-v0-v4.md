# S06 v0-v4 independent original-scope review

Verdict: pass against the roadmap scope.

The five checkpoints keep one explicit fixed-width Order format and compare
the same aggregate result across layouts. v0 counts actual row bytes and field
slots (two rows: 112 bytes, eight slots). v1 reads only region and amount
columns (40 bytes for the same two rows), while retaining row-order alignment.
v2 uses a real UTF-8 dictionary plus uint16 codes, reserves code zero for
None, validates malformed dictionaries/codes, and measures the complete
payload (22 dictionary bytes + 600 codes versus 3600 plain region bytes).
v3 derives immutable per-batch min/max statistics from the batch's own data,
uses closed interval checks without skipping boundary values, and returns
actual selected-column bytes and batch counts. Its reference sweep compares
results across many ranges, including gaps and overlap cases where min/max is
only a necessary condition. v4 measures slot point reads and full-row
updates: both layouts move 56 bytes, with one file operation for rows versus
four for columns. It explicitly avoids mutating v3 batches, whose statistics
would otherwise become stale, and states the partial-update risk.

All printed checkpoints include complete source fences. The strict replay
extracts only those fences into a fresh temporary package, sets `PYTHONPATH`
to that package, and executes each version's printed check. Focused tests cover
datatype validation, truncation, null/Unicode dictionary behavior, invalid
codes, closed boundaries, skipped batches, point bounds, and invalid updates.
I additionally observed actual `Path.open` reads/writes: row and column point
operations both transferred 56 bytes, with 1 versus 4 reads; updates likewise
performed 1 versus 4 writes and 56 total bytes. `None` round-tripped.
