## Review rationale

Each version names the concrete gap in the preceding experiment and preserves
the caller-visible event ordering. Two synchronous connections provide real
overlapping server transactions without sleep-based races. Isolation keywords
are allowlisted before SQL composition. v2/v3 accurately place snapshot
establishment at the first SELECT and distinguish PostgreSQL behavior from
the SQL standard's minimum guarantees.

v3 restores the temporary CLI patch when introducing the final scenario
branch. v4 explicitly distinguishes declared CHECK constraints from omitted
business invariants, and limits reconnection evidence rather than claiming
power-loss durability. Dependencies on v0 schema/transfer and v1 setup are
identified rather than supplied through hidden state.
